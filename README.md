# Reply Craft — いい返信で、つながりが広がる。

Xのポストのリンクから、投稿者自身の連続投稿を読み込み、あなたらしい返信を考えるWebツールです。青と白を基調にした画面で、取得した全文をChatGPTへ渡して、主張・結論を踏まえた絵文字つきの3案を依頼できます。AI接続済みのサーバー版では、サイト内で内容理解と返信生成を行います。トーン選択は不要です。

公開先： https://kajihrt1022.github.io/X-/

## 使い方

1. ポストのURLを入力します。「読み込む」で先に本文を確認するか、「返信を生成」で取得と依頼の準備を続けて実行します。
2. 公開版では「依頼文をコピー」を押し、「ChatGPTを開く」から貼り付けて送信します。取得・補足した本文の全体を渡し、主張・結論・注意点を整理したうえで3案を作るよう依頼します。絵文字は各案に必ず1つ以上入れます。
3. ChatGPTが示す内容理解と返信を確認し、Xで使います。ChatGPTの利用条件や回数制限が適用されます。このサイトがAI生成したようには表示しません。

「本文を貼り付ける」からの入力にも対応します。「あなたらしさを、もう少し」で質問、気づき、長さを調整できます。AIを使わない従来の定型文は「AIなしで下書きを作る」の中に移しました。Xへの自動投稿は行いません。

## URLとスレッドの読み取り

- 外部の非公式取得サービス **FxEmbed / FxTwitter** の公開API `https://api.fxtwitter.com/2/thread/{id}` を使います。APIキー・Xのログイン情報は不要です。ポストIDが同サービスへ送信されます。
- `x.com` / `twitter.com` のポストURLのみを許可します。共有用のクエリや画像・動画へのリンクも正規化します。任意のホストやローカルアドレスにはアクセスしません。
- 途中のポストURLからも、サービスが返した前後の連続投稿を読み取ります。同じ投稿者の投稿だけを重複なく時系列でまとめ、他ユーザーの返信は混ぜません。
- 取得した件数、各投稿の本文、リンク先の位置、最後に取得した投稿を表示します。APIがすべての続きを返す保証はなく、完全取得と断言しません。
- 削除・非公開、欠けた親投稿、上限超過が分かる場合は警告します。画像内の文字、動画・音声は解析しません。本文を確認・補足してから返信を作成できます。
- 上限は80投稿・60,000文字です。上限を超えた内容を黙って切り捨てず、一部取得として表示します。取得は25秒でタイムアウトし、キャンセルできます。
- 外部サービスの停止、アクセス制限、通信エラーの場合は理由を画面に表示します。以前の別の投稿を、新しいURLの取得結果として使いません。「本文を貼り付ける」に切り替えて利用できます。

公式の取得サービス仕様： https://docs.fxembed.com/api/introduction

## 生成モードと保存先

**GitHub Pages・HTML版の標準操作はChatGPTへの依頼準備です。** 公開HTMLにはAIの接続キーを埋め込みません。全文・読み取り手順・返信の条件を含む依頼文をコピーし、利用者がChatGPTへ貼り付けて送信します。自動でChatGPTへ投稿を送信することはありません。APIの追加設定やAPI料金は不要ですが、ChatGPT側の利用条件・回数制限が適用されます。この経路ではAIの回答はこのサイトに自動で戻りません。従来の文章パターンは、利用者が明示的に選んだ場合のみ実行し、内容理解を行わない簡易版と表示します。

**AI接続済みのサーバー版は、2段階で内容を読んで返信を作成します。** `REPLY_API_KEY` を設定するとOpenAIを使用します。`REPLY_MODEL` の初期値は `gpt-4.1-mini` です。

1. 全文から話題・主張・結論・条件や注意点を整理し、本文の根拠を正確に引用します。途中の失敗例や否定された意見と、投稿者の推奨を区別するよう依頼します。
2. 引用が実際の本文に存在することを検証してから、同じ全文と分析を渡して3案を作成します。各案は分析の根拠を参照し、絵文字と文字数の条件を守ります。「理解した内容」と各返信の「根拠」を画面で確認できます。理解の結果は履歴にも保存します。

本文にない引用、不正な根拠参照、AI接続エラーは表示し、黙って定型文へ切り替えません。この検証は引用の存在と形式を確かめるもので、意味理解の正確さを保証するものではありません。送信前に内容を確認してください。

サーバー版のAI利用時は投稿がOpenAIへ送信され、2回分のAPI利用料金がかかります。現在APIキーは未設定で、AI実通信・生成品質は未検証です。単体テストはAIの応答を差し替え、全文を両段階へ渡すこと、根拠検証、エラー処理を確認しています。APIキーを公開HTMLやブラウザ、Gitに埋め込まないでください。

保存した返信、最新20件の履歴、文体設定はブラウザのlocalStorageに保存します。旧kotoba版の保存済み返信と文章の長さ設定も引き継ぎます。以前のトーン指定・絵文字オフ設定は適用しません。ブラウザデータを削除すると消え、他の端末とは同期しません。サーバーは投稿・生成結果をファイルやDBに保存しません。

## 開発環境

Node.js 22.12以降（検証環境24.19）とnpmを使用します。既存の `/workspace/X-` を利用し、ユーザーの明示的な依頼がない限りworktreeは作成しません。

```sh
cd /workspace/X-
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev
```

Viteが5173、APIが3001で起動します。`npm run dev` の終了時に両方を止めます。バックエンドの変更後は開発コマンドを再起動してください。フロントエンドはHMRに対応します。日本語・英字フォントはローカル配信します。

AIを設定する場合は環境設定のシークレット `REPLY_API_KEY` を使用します。ローカルでは `.env.example` を `.env` にコピーして設定できます。実際の値をチャット・Git・ログへ出さないでください。AI接続先は `api.openai.com`、URL読み取り先は `api.fxtwitter.com` です。

## ビルド・公開

```sh
npm run build
npm start
```

ビルドした画面とAPIを3001（`PORT`で変更可）で配信します。個人用の開発サーバーで、認証機能はありません。APIキー設定済みのサーバーを公開する場合はアクセス制限を追加してください。

```sh
npm run build:standalone
```

`exports/kotoba.html` に、UIと生成処理を同梱した単一HTMLを出力します。本文入力・ChatGPT用依頼文の準備・任意の定型文による下書きはオフラインでも動作します。URLからの読み取りとChatGPTの利用にはネット接続が必要です。フォントは端末のものを使います。

GitHub Pagesは `.github/workflows/pages.yml` で公開します。`main`へのpushまたは手動実行で `site/index.html` を作成・配信します。PagesのSourceはGitHub Actionsに設定済みです。main以外から手動実行した場合はビルド・検証だけを行い、公開しません。

ワークフローの任意入力 `test_post_url` に公開ポストURLを指定すると、外部サービスへの実通信と、ブラウザでのURL読み取り・生成を検証します。通常のテストはネットワークに依存しないフィクスチャを使い、外部サービスへの実通信はこの明示的な診断に分けています。公開後のブラウザチェックは実際のサイトで、全文を含むChatGPT用依頼文の準備・コピーと、任意の定型文の生成・コピー・保存を確認します。

## 検証

```sh
npm test
npm run build
npm run build:standalone
# npm run dev または npm start を別ターミナルで起動して実行
TEST_BASE_URL=http://127.0.0.1:3001 npm run test:browser
```

単体テストは全文の利用、重み付き文字数、質問の保持、URLの制限、スレッドの並び順、別ユーザー・重複の除外、長文・欠落・上限・キャンセル・取得失敗を確認します。ブラウザテストはリンクだけでの取得・生成、編集・コピー・保存・履歴、再読み込み、検索・削除、設定、エラー回復、モバイル、HTML単体でのオフライン利用、絵文字必須とトーン選択不要を確認します。

ブラウザテストは `/usr/bin/chromium` を使用します。`CHROMIUM_PATH` と `TEST_BASE_URL` で変更できます。GitHubの実通信検証ではランナー標準のChromeを使用します。証明書検証を無効化するフラグは使いません。
