# Reply Craft — いい返信で、つながりが広がる。

Xのポストのリンクから、投稿者自身の連続投稿を読み込み、あなたらしい返信を考えるWebツールです。青と白を基調にした画面で、取得した本文を確認し、トーンを選び、3案を編集・コピー・保存できます。

公開先： https://kajihrt1022.github.io/X-/

## 使い方

1. ポストのURLを入力します。「読み込む」で先に本文を確認するか、「返信を生成」で取得と作成を続けて実行します。
2. 丁寧・フレンドリー・共感・実践・短文からトーンを選びます。「あなたらしさを、もう少し」で質問、気づき、長さ、絵文字を調整できます。
3. 気に入った案をその場で編集してコピーします。ハートで保存でき、元の投稿と3案は履歴にも残ります。

外部サービスを使わずに作成したい場合は「本文を貼り付ける」を選びます。Xへの自動投稿は行いません。

## URLとスレッドの読み取り

- 外部の非公式取得サービス **FxEmbed / FxTwitter** の公開API `https://api.fxtwitter.com/2/thread/{id}` を使います。APIキー・Xのログイン情報は不要です。ポストIDが同サービスへ送信されます。
- `x.com` / `twitter.com` のポストURLのみを許可します。共有用のクエリや画像・動画へのリンクも正規化します。任意のホストやローカルアドレスにはアクセスしません。
- 途中のポストURLからも、サービスが返した前後の連続投稿を読み取ります。同じ投稿者の投稿だけを重複なく時系列でまとめ、他ユーザーの返信は混ぜません。
- 取得した件数、各投稿の本文、リンク先の位置、最後に取得した投稿を表示します。APIがすべての続きを返す保証はなく、完全取得と断言しません。
- 削除・非公開、欠けた親投稿、上限超過が分かる場合は警告します。画像内の文字、動画・音声は解析しません。本文を確認・補足してから返信を作成できます。
- 上限は80投稿・60,000文字です。上限を超えた内容を黙って切り捨てず、一部取得として表示します。取得は25秒でタイムアウトし、キャンセルできます。
- 外部サービスの停止、アクセス制限、通信エラーの場合は理由を画面に表示します。以前の別の投稿を、新しいURLの取得結果として使いません。「本文を貼り付ける」に切り替えて利用できます。

公式の取得サービス仕様： https://docs.fxembed.com/api/introduction

## 生成モードと保存先

**GitHub Pages・HTML版は文章パターン生成です。** 全文から冒頭・途中・最後の言葉を拾い、構成の違う3案に整えます。意味理解を行うAIではありません。追加した気づきは指定の長さに応じて省略される場合があります。投稿への理解、質問の重複、実際の気持ちとの一致は送信前に確認してください。返信の獲得は保証しません。

AIによる全文をもとにした生成はサーバー版で利用できます。`REPLY_API_KEY` が設定されていればOpenAIを使用します。`REPLY_MODEL` の初期値は `gpt-4.1-mini` です。AIへの投稿送信と利用料金が発生します。現在APIキーは未設定で、AI実通信は未検証です。APIキーを公開HTMLやブラウザ、Gitに埋め込まないでください。

保存した返信、最新20件の履歴、文体設定はブラウザのlocalStorageに保存します。旧kotoba版の保存済み返信と文体設定も引き継ぎます。ブラウザデータを削除すると消え、他の端末とは同期しません。サーバーは投稿・生成結果をファイルやDBに保存しません。

## 開発環境

Node.js 22.12以降（検証環境24.19）とnpmを使用します。既存の `/workspace/X-` を利用し、ユーザーの明示的な依頼がない限りworktreeは作成しません。

```sh
cd /workspace/X-
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev
```

Viteが5173、APIが3001で起動します。`npm run dev` の終了時に両方を止めます。バックエンドの変更後は開発コマンドを再起動してください。フロントエンドはHMRに対応します。日本語・英字フォントはローカル配信します。

AIを設定する場合は環境設定のシークレット `REPLY_API_KEY` を使用します。ローカルでは `.env.example` を `.env` にコピーして設定できます。実際の値をチャット・Git・ログへ出さないでください。AI接続先は `api.openai.com`、URL読み取り先は `api.fxtwitter.com` です。

## ビルド・公開

```sh
npm run build
npm start
```

ビルドした画面とAPIを3001（`PORT`で変更可）で配信します。個人用の開発サーバーで、認証機能はありません。APIキー設定済みのサーバーを公開する場合はアクセス制限を追加してください。

```sh
npm run build:standalone
```

`exports/kotoba.html` に、UIと生成処理を同梱した単一HTMLを出力します。本文入力と文章パターン生成はオフラインでも動作します。URLからの読み取りにはネット接続が必要です。フォントは端末のものを使います。

GitHub Pagesは `.github/workflows/pages.yml` で公開します。`main`へのpushまたは手動実行で `site/index.html` を作成・配信します。PagesのSourceはGitHub Actionsに設定済みです。main以外から手動実行した場合はビルド・検証だけを行い、公開しません。

ワークフローの任意入力 `test_post_url` に公開ポストURLを指定すると、外部サービスへの実通信と、ブラウザでのURL読み取り・生成を検証します。通常のテストはネットワークに依存しないフィクスチャを使い、外部サービスへの実通信はこの明示的な診断に分けています。公開後のブラウザチェックは実際のサイトで本文入力・生成・コピー・保存を確認します。

## 検証

```sh
npm test
npm run build
npm run build:standalone
# npm run dev または npm start を別ターミナルで起動して実行
TEST_BASE_URL=http://127.0.0.1:3001 npm run test:browser
```

単体テストは全文の利用、重み付き文字数、質問の保持、URLの制限、スレッドの並び順、別ユーザー・重複の除外、長文・欠落・上限・キャンセル・取得失敗を確認します。ブラウザテストはリンクだけでの取得・生成、編集・コピー・保存・履歴、再読み込み、検索・削除、設定、エラー回復、モバイル、HTML単体でのオフライン利用を確認します。

ブラウザテストは `/usr/bin/chromium` を使用します。`CHROMIUM_PATH` と `TEST_BASE_URL` で変更できます。GitHubの実通信検証ではランナー標準のChromeを使用します。証明書検証を無効化するフラグは使いません。
